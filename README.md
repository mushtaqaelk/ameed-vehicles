# نظام العميد الإلكتروني لمتابعة العجلات

نظام ويب يعمل على الهاتف لمتابعة عجلات جامعة العميد. يشمل:
- الجدول الآني للعجلات داخل الجامعة وخارجها
- تسجيل الخروج والدخول عند البوابات
- صرفيات الوقود وطلبات الصيانة والغسل، مع دورة الموافقة
- تقييم السائقين بالنقاط
- التقارير القابلة للطباعة والتصدير إلى Excel

التطبيق كله في ملف واحد، `index.html` (HTML وCSS وJS عادي دون أي خطوة بناء)، ويستخدم Firebase (Auth + Firestore) وGitHub Pages.

## التجربة فوراً (وضع العرض التجريبي)
ما دام `firebaseConfig` داخل `index.html` غير مُعدّ، أو عند إضافة `?demo=1` إلى الرابط، يعمل النظام على قاعدة بيانات محلية داخل المتصفح فيها بيانات تجريبية، دون أن يمس القاعدة الحقيقية. تظهر في شاشة الدخول أزرار لكل دور، وكلمة المرور لجميعها `demo1234`.

## الأدوار
| الدور | الصلاحيات |
|---|---|
| مدير النظام (admin) | كل الصلاحيات: المستخدمون، والمواقع، والإعدادات، والاستيراد، وسجل التدقيق |
| مدير الآليات (fleet) | العجلات والسائقون، والموافقة على الطلبات وإنجازها، والنقاط والتقييم لكل السائقين |
| مدير القسم (supervisor) | إضافة الشكر والتقدير والعقوبات (مع النقاط) والتقييم للسائقين التابعين له فقط |
| الاستعلامات (gate) | تسجيل الخروج والدخول في مواقعه فقط، والجدول الآني |
| المالية (finance) | تأييد المبالغ أو رفضها، والملخص المالي |
| سائق (driver) | طلبات الوقود والصيانة والغسل، وطلب التأخير وطلب المساعدة، وتعديل هاتفه وعنوانه وصورته (لا اسمه)، وعرض ملفه ونقاطه |
| الإدارة العليا (viewer) | عرض فقط |

## دورات الطلبات
- **الوقود:** جديد ← موافقة مدير الآليات ← بانتظار المالية ← تأييد المالية ← منجز
- **الصيانة:** جديد ← موافقة ← قيد التنفيذ (تتحول العجلة تلقائياً إلى "في الصيانة") ← إدخال الكلفة الفعلية ← بانتظار المالية ← منجز
- **الغسل:** جديد ← منجز. إذا كانت له كلفة يمر على المالية أولاً. المكان: كراج العتبة أو خارجي.
- **الورشة في الصيانة:** كراج العتبة، أو خارجي مع كتابة اسم المكان.
- **طلب التأخير (من السائق):** جديد ← موافقة مدير الآليات. لا تُعدّ العجلة متأخرة قبل الوقت المعتمد.
- **طلب المساعدة (من السائق):** يظهر فوراً كتنبيه عاجل لمدير الآليات ← جارٍ التعامل ← تمت المعالجة.
- يمكن الرفض في أي مرحلة، ويُكتب السبب.

## الربط بقاعدة البيانات الحقيقية
1. أنشئ مشروعاً في [Firebase Console](https://console.firebase.google.com) باسم `ameed-vehicles`. تكفي الخطة المجانية (Spark)، لأن الصور تُضغط داخل المتصفح وتُحفظ في Firestore دون Storage.
2. من **Build > Authentication > Sign-in method** فعّل **Email/Password**.
3. من **Build > Firestore Database** أنشئ قاعدة البيانات (المنطقة `eur3` أو الأقرب لك).
4. من تبويب **Rules** الصق محتوى الملف [`firestore.rules`](firestore.rules) كاملاً واضغط **Publish**.
5. من **Project settings > General > Your apps** أضف تطبيق ويب (`</>`) وانسخ قيم `firebaseConfig` إلى المتغير نفسه في أعلى الـ script داخل `index.html`.
6. من **Authentication > Settings > Authorized domains** أضف `mushtaqaelk.github.io`.
7. افتح الموقع. ستظهر شاشة **"إنشاء حساب مدير النظام الأول"**، وبعدها أنشئ حسابات الموظفين والمواقع من تبويب **الإدارة**.

أسماء المستخدمين تتحول داخلياً إلى `username@ameed-vehicles.app` (هذا ليس بريداً حقيقياً). لإعادة تعيين كلمة مرور موظف استخدم **Authentication** في Firebase Console، أو أوقف حسابه وأنشئ له حساباً جديداً.

## النشر على GitHub Pages
من **Settings > Pages** اختر **Deploy from branch**، ثم الفرع `main` والمجلد `/ (root)`. بعد كل تحديث قد تظهر النسخة القديمة عند أول تحميل للصفحة، فأعد التحميل مرة ثانية.

## الإعدادات الافتراضية (قابلة للتعديل من تبويب الإدارة)
- التنبيه بعد 12 ساعة من خروج العجلة
- التنبيه قبل 30 يوماً من انتهاء السنوية
- تبديل الدهن كل 5,000 كم
- تمييز التعبئة التي يزيد استهلاكها على معدل العجلة بأكثر من 25% (للعلم فقط، ويُحسب المعدل بعد 3 تعبئات على الأقل)

## نقاط السائقين
- النقاط **سنوية**: رصيد كل سائق يبدأ من صفر في بداية كل سنة.
- يضيف مدير الآليات (لكل السائقين) أو مدير القسم (لسائقي قسمه) **شكراً وتقديراً** بنقاط موجبة، أو **عقوبة** بنقاط تُخصم، باستخدام عدّاد، مع السبب ورقم الكتاب.
- قائمة السائقين مرتبة حسب النقاط أو أبجدياً، مع بحث بالاسم.
- ملف السائق يعرض صورته وتفاصيله ونقاطه ونجومه وشكره وعقوباته للسنة المختارة، مع تقرير كامل لكل السنوات.

## البيانات التجريبية والاستيراد
- كل البيانات التجريبية معلَّمة بـ `demo:true`، ويحذفها زر واحد في تبويب الإدارة دون أن يمس البيانات الحقيقية.
- استيراد العجلات والسائقين من Excel (من تبويب الإدارة) إضافي فقط، والصفوف المكررة تُتجاوز.

## العمل دون إنترنت
- تفعيل Firestore offline persistence يحفظ الحركة على الجهاز، ثم يزامنها تلقائياً عند عودة الاتصال.
- الـ service worker (`sw.js`) يتيح فتح الصفحة دون شبكة.
- يمكن تثبيت التطبيق على الشاشة الرئيسية للهاتف (PWA).

## الاختبار
```bash
node --check sw.js
node tests/smoke.test.js          # Playwright + Chromium على قاعدة البيانات التجريبية
# إن لم يتوفر الوصول إلى cdnjs: XLSX_PATH=/path/to/xlsx.full.min.js node tests/smoke.test.js
```
يغطي الاختبار كل الأدوار ودورات الطلبات والنقاط والتقارير ووضع الطباعة والاستيراد، ويحفظ لقطات الهاتف (375px) والطباعة في `tests/screenshots/`.
